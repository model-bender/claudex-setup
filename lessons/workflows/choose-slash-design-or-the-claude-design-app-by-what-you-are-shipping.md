# Pick /design in Claude Code When the Output Becomes Code, the Claude Design App When It Stays a Picture

## TL;DR

If the design becomes a real page or app in a codebase you already have open, use /design in Claude Code: the chosen artboard goes straight to implementation. If it is a poster, flyer or social graphic, use the Claude Design app.

## Why it matters

Tristen O'Brien gives three reasons for the split, and the load-bearing one is the handoff: in Claude Code 'if you give it the name of the artboard, it's going to start building it right then and there', whereas in the app 'you do have to export it before handing it over to Claude'. The second is co-location, the design and the code never leave the same place. The third is the artefact itself: 'if this is going to be a poster or a flyer or a social graphic, then you're going to want to do it inside of the Claude app, cuz you don't need Claude code to create something like that.' Picking by tool preference instead of by artefact buys you an export step and a second context for no gain.

## How to apply

Ask what the artefact becomes. Becomes code in a repo you have open: run /design in Claude Code. Stays an image or print piece: use the Claude Design app. Both surfaces were still in research preview at the time of recording, so expect the canvas UI to move; the routing rule survives the UI churn.
