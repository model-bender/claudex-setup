# Read the tool's entire docs and trial every feature in deliberate exploration phases, don't rely on real work to surface them

## TL;DR

Doing real work only teaches you the features you stumble into; periodically read the complete Claude Code / Codex docs end to end, try every hotkey and feature deliberately, and run a focused exploration phase whenever a paradigm-shifting release lands.

## Why it matters

A Meta L7 answering "what's the best way to test new workflows, just doing real work?" is explicit that work alone has a ceiling: "there is a limitation of what you will learn." His practice is to read all of OpenAI's or Claude Code's entire docs and then actually try the things they describe ("try all the hotkeys, try all these things"), because "you'll be surprised how much of your work will change based on some hidden feature that you may never run into if you were just working." He balances this against novelty-chasing: stick with the workflow you're a professional at, and open an exploration phase only when there's a big delta (a new model, or a paradigm-shifting product launch).

## How to apply

Schedule exploration as its own activity, separate from delivery work: pick the official docs for your primary harness (Claude Code or Codex), read them cover to cover, and exercise each keybinding, slash command, and setting as you go rather than skimming. Repeat the pass when a major release or paradigm-shift event ships; otherwise resist switching tools for every trend and keep compounding on the harness you know deeply.
