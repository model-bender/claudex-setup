# Skip Claude Design's Wireframe Stage for a Single Page: Spend It on Journeys and App Screens

## TL;DR

A wireframe pass before a one-page landing page is measurably wasted spend; go straight to high fidelity. Save the wireframe stage for multi-page funnels, app screens, and branding or packaging exploration.

## Why it matters

This one was actually measured: a three-concept mid-fi wireframe pass for a landing page cost ~7% of a weekly design allowance and the output was discarded, "that was a waste of my session limit."

With a design system and brand-concept doc attached, high fidelity one-shots a landing page anyway, and the tweaks panel covers the style exploration the wireframe was supposed to surface.

**Wireframe value tracks structural uncertainty**, and a single known page has almost none.

> **Scope note vs [[design-philosophy-first-strip-prd-then-pick-one-ux-direction]]**, which says default to wireframe/black-and-white first. That still holds where structure is genuinely open, multi-page journeys, app screens, branding. This is the narrow exception: one page, known structure. The existing lesson asserts wireframe-first on reasoning; this one is the only measurement either way. Treat them as a scope split, not a contradiction.

## How to apply

For one page with a known structure: prototype → high fidelity, attach the design system and brand doc, build.

Reach for wireframe when laying out a multi-page journey (page 1 → 2 → 3 of a funnel), designing an actual mobile or desktop app's screens, or exploring branding, logo, and packaging directions.

If you do run one, its intake questions control the cost, number of concepts, fidelity (sketchy / clean / mid-fi / mix), light vs dark, and "decide for me" is a valid answer.

Cheaper still: do concept exploration in a regular Claude chat.
