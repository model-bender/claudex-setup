# Vibe-Test a Shared CLAUDE.md Rule for Weeks Before Landing It on the Team

## TL;DR

Before committing a team-wide CLAUDE.md rule to the repo, run it privately for a few weeks and gather informal feedback, since there's no solved evaluation method for this yet.

## Why it matters

John Kim says 'there's got to be some form of evaluations here' for compound-engineering CLAUDE.md commits but admits 'a lot of people are just using vibes,' so his actual practice is: trial it for weeks, then land it and ask for feedback.

## How to apply

Keep a candidate team-wide CLAUDE.md addition local/uncommitted, use it yourself for a few weeks, then commit it and explicitly solicit teammate feedback rather than assuming it's correct on day one.
